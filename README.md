# kconc · Linux 内核并发检错与可信优化

两个线程各给寄存器设置一位，为什么最后只留下一位？打上补丁后，怎样确认测试又走到了那组交错？kconc 在真实 Linux 内核里记录出错的执行顺序，用它检查修复后的行为。项目还用一项受限的驱动读取优化，探索怎样同时验证改写的正确性和收益。

## 团队做了哪些探索

上一版中，并发检错模块已经能够稳定重放受测路径，并在修复内核上完成回归。我们也在 BMA400 的六字节读取上验证了一个想法：只要确认格式转换函数什么也不做，就可以省去每帧的六次空调用。这一版，我们把问题从一个专用入口扩展到了驱动源码：换一个寄存器窗口，或者由调用方决定读取长度，工具能否自己判断哪些地方仍然适用这条规则？

为此，我们把判断分在两个时机。分析驱动源码时，工具核对接收缓冲区能否容纳本次读取，以及寄存器参数在求值时会不会改变程序状态。创建 regmap 时，工具根据这个对象的实际格式、转换函数和回调观察设置，确定它能否跳过空转换。这样，同一个对象反复读取时可以复用初始化时的判断，每次仍核对读取长度，确认不了条件的调用仍沿用原来的处理方式。

我们用 Coq 证明助手检查了这项局部改写，又在同一套受控 RAM 总线上换了寄存器窗口，核对规则能否复用。最后接入 BMA400 原生驱动和软件 SPI 外设，逐帧比较读取结果：八帧数据完全一致，空调用从 48 次降到 0 次，开启回调观察后又恢复到 48 次。

## 回看一次寄存器更新

两个调用者分别要把寄存器中的一个位置为 1。初值是 0，两个操作按任一串行顺序完成后都应读到 3。在演示选取的执行中，两个调用者都读到了旧值，最后只读回 1。打开报告，可以沿着各自的读写事件找到对应的内核源码行，再打开一次实际重执行的记录，与原始路径逐项比较。

工具在 QEMU/KVM 中运行真实 Linux 内核。RAM 测试总线提供可复位的初态。受控调用方分别比较拆开的读改写与 `regmap_update_bits()`，以及不同调用者分用两把锁与共用一把锁。工具先采集两种串行顺序，生成交错候选，执行时核对目标访问与控制交接，再用最终寄存器值或临界区进入、退出事件判定性质。它还可按执行反馈分配尝试预算，缩减输入时通过重执行确认原有违例。

| 正式批次 | 判据与结果 |
| --- | --- |
| 原构建路径重放 | 8 个用例各执行 20 次。**159/160** 次完整匹配关键路径。1 次路径偏离计入分母，8 组均达到预定的每组至少 19 次匹配。 |
| 修复版回归 | 在修复构建上重新采样并定位对应操作，8 个用例各执行 5 次。**40/40** 次命中候选，40 次性质判定有效，违例 0 次。 |

两批分别计数。原构建的逐次重放记录保存完整匹配及偏离分类，修复版的验收记录分别列出正式批次和早期尝试。结论适用于这些构造的调用方、输入和交错。离线演示选取其中一例，附原始执行、一次重执行和该例的五次修复回归。[运行与证据复核](docs/RUNNING.md)

## BMA400 一次六字节读取能省多少

为了单独看清 regmap 自身的软件开销，我们先用受控 RAM 总线测量专用入口。三轴样本占六字节，一次完整调用包括三笔两字节传输。正常 `-O2` 下，原版平均 **61.20 纳秒**，跳过已知空转换后为 **41.44 纳秒**。一次约 60 纳秒的操作平均省下 **19.76 纳秒**，配对耗时下降 **31.47%**（95% 区间 23.41% 至 40.04%）。三种实现轮换启动，每种对照保留 24 对正式批次。只缓存函数指针时，降幅估计为 5.20%，区间跨零。

我们也在 BMA400 原生驱动和软件 SPI 外设上验证了推广后的版本：8 帧数据逐字节一致，空调用从 48 次降到 0 次，开启观察后恢复为 48 次；计入加锁和模拟 SPI 传输，完整读取平均从 **253.47 降至 242.31 纳秒**，省下 11.16 纳秒，配对降幅 4.95%（95% 区间 −2.58% 至 11.04%），这条路径尚未测出稳定提速。

### 方法的泛化性

在同一套受控 RAM 总线实验中，我们把起始寄存器从 BMA400 的 `0x04` 移到 KX022A 的 `0x06`。六字节读取、三笔传输和计时方式均相同。换窗口后，每帧仍省去六次空调用，读出的字节一致。KX022A 窗口下每次平均省 **18.54 纳秒**，配对耗时下降 **32.20%**（95% 区间 28.68% 至 35.50%）。这个对照检验了同一条规则在不同寄存器窗口上的复用。

### 工具怎样判断哪些读取可以改

在锁定配置的加速度计驱动目录，工具检查了 44 处批量读取，8 处满足改写条件。对变长读取，工具还要从源码找到接收缓冲区的容量依据。实际分配长度与请求相符的调用可以通过。同一条声明里又改写了缓冲区指针，或寄存器参数的计算带有赋值时，工具保留原调用。[扫描与生成补丁](docs/RUNNING.md)

生成器把局部 Coq 证书与生成的 C 源码绑定。证明依赖本次调用期间对象有效、私有格式字段稳定、缓冲区可写且容量足够。准入对象仍走原有缓存或总线路径，读取成功后才可能跳过转换。传输错误沿原路径返回，释放后重新创建的对象重新选定资格。[局部证明与源码检查](proofs/init-regmap/)

项目也在各自的原模型上复现了 PromisingComp 和 SEQ 的优化算法与定理。上述空转换规则和对应的局部证明由本队编写。[证明工件](proofs/) · [工具与源码版本](configs/optimization/)

## 开始使用

从仓库根目录运行以下命令可查看入口。Python 需要 3.11 或更新版本。

```bash
python3 -B kconc.py --help
python3 -B kconc.py commands
```

已有离线演示材料时，解压后用浏览器打开 `demo/index.html`。要从原始记录重新计算表格并生成页面，使用材料中的 `kit/bundle.json`。演示材料、镜像和完整运行档案单独提供。要运行真实内核，使用 WSL Debian、QEMU/KVM x86_64、openEuler 24.03 LTS SP3 用户空间和锁定的实验内核。[运行说明](docs/RUNNING.md) · [环境与构建](docs/BUILDING.md)
