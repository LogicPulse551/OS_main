# kconc · Linux 内核并发检错与可信优化

两个并发操作按怎样的顺序执行会出错，修复后还能否观察到同样的错误？驱动里一项看似多余的工作，在哪些条件下可以省略，又能节省多少时间？kconc 用 Linux 寄存器访问子系统 regmap 演示这两种检查。

## 回看一次寄存器更新

两个调用者分别要把寄存器中的一个位置为 1。初值是 0，两个操作按任一串行顺序完成后都应读到 3。在演示选取的执行中，两个调用者都读到了旧值，最后只读回 1。打开报告，可以沿着各自的读写事件找到对应的内核源码行，再打开一次实际重执行的记录，与原始路径逐项比较。

工具在 QEMU/KVM 中运行真实 Linux 内核。RAM 测试总线提供可复位的初态。受控调用方分别比较拆开的读改写与 `regmap_update_bits()`，以及不同调用者分用两把锁与共用一把锁。工具先采集两种串行顺序，生成交错候选，执行时核对目标访问与控制交接，再用最终寄存器值或临界区进入、退出事件判定性质。它还可按执行反馈分配尝试预算，缩减输入时通过重执行确认原有违例。

| 正式批次 | 判据与结果 |
| --- | --- |
| 原构建路径重放 | 8 个用例各执行 20 次。**159/160** 次完整匹配关键路径。1 次路径偏离计入分母，8 组均达到预定的每组至少 19 次匹配。 |
| 修复版回归 | 在修复构建上重新采样并定位对应操作，8 个用例各执行 5 次。**40/40** 次命中候选，40 次性质判定有效，违例 0 次。 |

两批分别计数。原构建的逐次重放记录保存完整匹配及偏离分类，修复版的验收记录分别列出正式批次和早期尝试。结论适用于这些构造的调用方、输入和交错。离线演示选取其中一例，附原始执行、一次重执行和该例的五次修复回归。[运行与证据复核](docs/RUNNING.md)

## BMA400 一次六字节读取能省多少

读取加速度计的三轴数据需要六个字节。实验中的同步 RAM 总线将其分成三笔两字节传输。在指定的 8 位 regmap 对象上，原入口在读取成功后，仍对六个字节逐一调用同一个空转换函数。我们为这个对象编写的专用入口会检查函数地址，跳过已知的空调用，保留其他转换。对象身份或配置不适用时，入口选用公共读取路径。

生成器核对指定源码、配置及工具指纹，通过 Coq 检查后输出两版 C 源码和局部证书。保证涵盖返回值、读取的数据、出错前已写入的前缀及约定的总线和跟踪事件。它依赖对象归属明确、读取期间回调稳定、缓冲区有效且与对象分离等条件。Linux 总线、编译器和构建过程属于可信基础。两版内核另做功能检查，覆盖正常读取、分笔出错及公共入口回退。[规则及其适用条件](configs/optimization/bma400-six-byte.json)

| 相对原版的变换 | 每次完整读取的配对耗时降幅 | 95% 区间 |
| --- | ---: | ---: |
| 仅缓存回调指针 | 5.20% | −7.58% 至 17.24% |
| 跳过已知空回调 | **31.47%** | **23.41% 至 40.04%** |

三种内核使用相同的正常 `-O2` 配置、相同的计时驱动和 RAM 总线。六轮轮换启动顺序，共 18 次正式启动，每批执行 20,000 次完整读取。去掉协议指定的预热后，每种对照保留全部 **24 对**。耗时降幅按轮配对比率取几何平均，区间按整轮重采样。跳过空调用平均每次节省 **19.76 ns**。测量范围是虚拟机中的 regmap 调用，物理 SPI 传输和传感器采样延迟在计时范围之外。

项目也独立复现了两组论文工件。PromisingComp 在原模型上运行了常量传播、公共子表达式消除、死代码消除和循环不变量外提。SEQ 在原模型上运行了读后读转发、写后读转发和死存储消除。每组保留原算法的输入输出、最终定理和假设。上表的收益来自本队的 BMA400 空回调规则。[证明工件](proofs/) · [工具与源码版本](configs/optimization/)

## 开始使用

从仓库根目录运行以下命令可查看入口。Python 需要 3.11 或更新版本。

```bash
python3 -B kconc.py --help
python3 -B kconc.py commands
```

已有离线演示材料时，解压后用浏览器打开 `demo/index.html`。要从原始记录重新计算表格并生成页面，使用材料中的 `kit/bundle.json`。演示材料、镜像和完整运行档案单独提供。要运行真实内核，使用 WSL Debian、QEMU/KVM x86_64、openEuler 24.03 LTS SP3 用户空间和锁定的实验内核。[运行说明](docs/RUNNING.md) · [环境与构建](docs/BUILDING.md)
